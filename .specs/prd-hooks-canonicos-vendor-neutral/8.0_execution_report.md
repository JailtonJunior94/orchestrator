## Riscos Residuais
- **`.claude/settings.json` deste repositório com `env GOVERNANCE_PRELOAD_MODE=warn` embutido no comando do hook PreToolUse**, em vez do comando puro que `defaultClaudeSettings()` produz para projetos consumidores. Causa raiz: qualquer comando Bash sem alvo de arquivo extraível (a maioria dos comandos usados durante a implementação: `go build`, `go test`, `git status`, etc.) é permanentemente bloqueado por `validate-preload.sh` quando `GOVERNANCE_PRELOAD_CONFIRMED` não está setada no processo que invoca o hook — e não há mecanismo, a partir de uma tool call deste agente, para setar essa variável no processo pai que a Claude Code/Agent SDK usa para rodar os hooks. Ativar a fiação real e completa (idêntica ao `defaultClaudeSettings()`) travaria integralmente a própria sessão executora, sem meio de reverter (Bash fica bloqueado após o primeiro comando). A mitigação adotada relaxa apenas o fallback final "governança não carregada" de `validate-preload.sh`; `git-operation-gate.sh` e `hook-prereq-gate.sh` (as duas defesas com poder real de bloqueio: comandos git não solicitados, comandos destrutivos, edição de código sem skill de linguagem) permanecem totalmente ativos e não dependem de `GOVERNANCE_PRELOAD_MODE`. Risco residual: um usuário real que clone este repositório e abra uma sessão Claude Code herdará esse mesmo relaxamento pontual no aviso de "confirme que leu AGENTS.md", não nos gates de bloqueio real. Recomenda-se ao dono do repositório decidir, em tarefa separada, se o self-dogfood deve usar o comando puro (aceitando que qualquer sessão futura precisará setar `GOVERNANCE_PRELOAD_CONFIRMED=1` no ambiente antes de operar neste repo) ou manter esta mitigação.
