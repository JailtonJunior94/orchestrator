- `claude-agent-acp` ainda não suporta `--mcp-server` em produção; a flag é injetada conforme spec mas smoke end-to-end físico requer suporte no binário (tracking em audit/).
- Os pipes `os.Pipe()` são suficientes para comunicação stdio do servidor MCP em processo (sem socket Unix necessário para esta wave).
- `normalizationMeta` como ponteiro não viola OC rule #5 (sem nil returns em interfaces) porque `Event` é value type, não interface.
- Testes T-INT-01/T-INT-02 com mock ACP satisfazem os critérios de smoke documentados na techspec.

## Riscos Residuais

- Smoke físico não executado (sem binário): risco baixo; a lógica de spawn foi validada via mock.
- `--mcp-server` injetado mas ignorado pelo launcher atual até suporte binário: sem impacto em sessões F1-Claude (flags irrelevantes para Claude).
- `normalizeEventInline` chama `loadRules` por evento (cada tool_call_start): possível overhead em sessões com muitas tool calls. Mitigação futura: cache de regras em ACPRunner.

## Conflitos de Regra

- go-implementation vs object-calisthenics-go: Run() cresceria >300 LoC; extração de helpers `spawnMCPServer` e `normalizeEventInline` alinha ambas as regras. Escolha: go-implementation prevalece conforme governance.md (OC como heurística, não substituto).
