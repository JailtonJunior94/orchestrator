## Bug Crítico Encontrado e Corrigido

**probe.resolve() não passava spec.FixedArgs ao NewBinaryLauncher (RF-05)**

- Antes: `return specs.NewBinaryLauncher(path), nil`
- Depois: `return specs.NewBinaryLauncher(path, spec.FixedArgs...), nil`
- Impacto: sem fix, copilot era iniciado sem `--acp` e entrava em modo legado (legacy CLI) em vez de ACP server
- Diagnóstico: `ps aux` mostrava `copilot` sem `--acp`; log copilot mostrava "Starting Copilot CLI" em vez de "Starting ACP server (stdio)"
- Fix aplicado em: `internal/runtime/probe/probe.go`, comentário explicativo adicionado
- Teste de regressão: T-07 em `internal/runtime/probe/probe_test.go` validando `spec.FixedArgs` presentes no `Command()` do launcher

## Suposições
- O cancel_reason=permission_denied é comportamento esperado do copilot ACP durante execute-task; não é falha de autenticação ou ambiente (RF-16: harness recusa permissões por design)
- Os 3 unknown events (`available_commands_update`, `config_option_update`) são extensões Copilot-específicas do protocolo ACP não mapeadas no modelo de eventos atual; não causam falha funcional
- O critério DoD `UnknownEventsCount == 0` não é atingível nesta versão para Copilot; a harness deve expandir o event model em iteração futura para mapear esses eventos Copilot-específicos
- O campo `tool=copilot` ausente da telemetria (RF-21 parcial) é limitação da struct `ACPSessionEvent` que não possui campo `Tool`

## Riscos Residuais
- **UnknownEventsCount=3**: eventos `available_commands_update` e `config_option_update` do Copilot ACP não mapeados no event model. Requer tarefa de mapeamento em PRD futuro.
- **RF-21 parcial**: telemetria não emite `tool=copilot` — struct `ACPSessionEvent` em `internal/telemetry/acp.go` carece de campo `Tool`. Baixa prioridade para este PRD; não afeta funcionamento do runtime.
- **Smoke incompleto por permission_denied**: a sessão ACP termina quando copilot solicita permissão (terminal/filesystem); a harness cancela conforme RF-16. O fluxo completo de execute-task não pode ser validado sem `accessMode=bypassPermissions` ou ambiente pré-aprovado.
- **VS Code shim**: o binário copilot do VS Code Copilot Chat extension não suporta `--acp` e entra em modo legado. Ambientes com o shim primeiro no PATH produzirão sessão inválida. Documentado em ADR-007.
