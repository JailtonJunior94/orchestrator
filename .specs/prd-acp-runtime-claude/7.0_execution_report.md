## Decisões Técnicas

### JSONLWriter com buffer em memória

A `fs.FileSystem` (incluindo `FakeFileSystem`) expõe apenas `WriteFile` (overwrite),
sem suporte a append nativo. A abordagem adotada: manter buffer `[]byte` em memória,
protegido por `sync.Mutex`, acumulando o conteúdo e reescrevendo o arquivo completo
em cada `Append`. Thread-safe e compatível com ambas as implementações de filesystem.

### report.go — regex para substituição idempotente

Detecção de `## Runtime ACP` via `(?m)^## Runtime ACP$` (regex multi-line);
busca de próxima seção `^## ` para delimitar o bloco a substituir. Garante que
seções adjacentes não são removidas.

### runtime.Summary em internal/runtime/summary.go

Criado em `internal/runtime/` (não em `persistence/`) para evitar dependência
circular e para que o tipo seja consumido tanto por `persistence.EnrichReport`
quanto pelo futuro `ACPRunner` (tarefa 9.0).

## Riscos Residuais

- `renderSection` tem 75.0% de cobertura: o branch de erro do template é inalcançável
  em runtime normal (template parseado com `template.Must` na inicialização).
- `FakeFileSystem` não suporta append nativo; se `OSFileSystem` for utilizado em
  produção, o comportamento de reescrita total pode gerar overhead em arquivos
  grandes. Aceitável para logs de task (eventos contados em centenas, não milhões).
