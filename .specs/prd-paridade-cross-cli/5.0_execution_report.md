## Suposições
- `Concurrent` e `BatchSize` do config hierárquico são consumidos pelo `RunLoop` via `opts` (ADR-018); o `acpInvoker` recebe `MaxRetries` e `RetryBackoffMultiplier` pois são os campos que afetam o comportamento do runner/invoker por sessão.
- O `RunLoop` não foi modificado pois ele já lê `opts.Concurrent`/`opts.BatchSize` diretamente — wiring completo nessa camada seria subtarefa de integração do CLI (flags `--concurrent`/`--batch-size` ainda não expostas no `task_loop.go`).
- `opts.ActivityTimeout` passa como override quando `> 0`, conforme a semântica de "flag explícita vence config" (ADR-016).

## Riscos Residuais
- `opts.Concurrent` e `opts.BatchSize` ainda não têm flags CLI no `cmd/task_loop.go`; o config hierárquico para esses campos só funciona via arquivo `.claude/config.yaml` (não via flag). Isso é consistente com o estado atual (ADR-018) e pode ser adicionado em tarefa futura.
- Drift entre `config.Runtime` e `runtime.RuntimeConfig`: mitigado por `BuildRuntimeConfig` como ponto único de mapeamento + testes de mapeamento 1:1.
