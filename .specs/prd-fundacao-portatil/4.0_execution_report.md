## Suposições
- `RetryAttempts` no Summary registra o número de retries extras (0 = sucesso na 1a tentativa).
- O sleep de backoff é injetável via `acpInvokerSleepFnOption` para testes sem espera real.
- `selectBatch` interrompe a seleção quando o seletor retorna a mesma task em loop (dedup por ID).
- O `FinalReviewer` em `RunLoop` é sempre chamado sequencialmente após o batch (sem race).
- Falhas no `executor` durante execução paralela resultam em halt-on-first-error por batch.

## Riscos Residuais
- Não-determinismo de ordering: tasks em batch podem completar fora de ordem; `TasksCompleted` preserva a ordem de declaração do batch.
- `stubReviewer` em testes paralelos pode ter race se `results` for mutado concorrentemente; mitigado por execução serial do FinalReviewer após `wg.Wait()`.
- Falhas de `selectBatch` com seletor que retorna mesma task repetidamente: o dedup por ID evita loops infinitos.
