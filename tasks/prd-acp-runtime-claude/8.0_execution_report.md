## Decisões Técnicas

1. **IOProvider injetável** — `acpClient` aceita `IOProvider` interface para testes in-process sem subprocess; produção passa nil e usa `startProcess`.
2. **Channel com buffer 64** — Evita bloqueio do SDK enquanto o consumidor processa; sessões normais têm volume baixo.
3. **`closeChannel` idempotente via `sync.Once`** — Garante que o canal fecha exatamente uma vez independente de múltiplos callers.
4. **acpfake usa `AgentSideConnection` real do SDK** — Conforme decisão #21 da techspec; sem mock do protocolo.
5. **Marcador sentinela para `AppendSessionEnd`** — Update vazio detectado por `isSessionEnd()` causa retorno do `Prompt` com `StopReasonEndTurn`.
6. **`AppendRequestPermission` usa `Plan` com prefixo `"requestPermission:"`** — Protocolo interno do fake para disparar `conn.RequestPermission()`.

## Riscos Residuais

- `killProcess` timeout path (SIGKILL após 2s) é exercitado apenas pelo `TestAcpClient_Close_WithRunningProcess`; a branch exata do SIGKILL não é coberta (dependente de timing do SO).
- `Authenticate`, `Cancel`, `ListSessions`, `ResumeSession`, `CloseSession`, `SetSessionConfigOption`, `SetSessionMode` no `fakeAgent` são stubs — não chamados pelo protocolo em fluxo normal de `Initialize + NewSession + Prompt`.
- `clientImpl.RequestPermission` cancela imediatamente (RF-16); o canal de eventos não emite evento específico de `permission_denied` — isso é responsabilidade do `ACPRunner` via `context.CancelCause` (task 9.0).
